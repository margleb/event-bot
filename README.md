# Event Bot

Telegram-бот с Mini App, который подбирает мероприятия по предпочтениям и
собирает компании на конкретные события. Telegram используется для входа,
уведомлений, еженедельных подборок и обратной связи; основной пользовательский
сценарий находится в визуальном приложении.

## Возможности

- визуальное заполнение интересов, удобных дней, бюджета и размера компании;
- хранение профилей в SQLite — они переживают перезапуск бота;
- импорт реальных мероприятий Москвы на 30 дней из KudaGo, Timepad и
  Ticketmaster через официальные API; источники с ключами включаются через
  окружение;
- брендированный логотип источника и ссылка на оригинал в карточках Telegram
  и Mini App;
- схлопывание одинаковых анонсов, пришедших одновременно из разных каталогов;
- смысловой подбор до 5 событий через OpenAI embeddings и NumPy;
- жёсткие фильтры города, даты и бюджета до векторного ранжирования;
- автоматический fallback на прежнее сравнение тегов без ключа или вектора;
- сохранение событий и поиск компании внутри Mini App;
- запросы на знакомство с взаимным раскрытием контактов;
- глобальная симметричная блокировка и лимит пяти запросов за 24 часа;
- еженедельная персональная подборка в выбранный пользователем день;
- защита автоматической рассылки от повторов после перезапуска бота.
- Telegram Mini App с мобильной лентой, карточками, отметками и редактором
  профиля;
- добровольный подбор постоянной группы из 3–5 человек по пересекающимся
  интересам, с отдельной вкладкой «Группа» и уведомлением о готовности;
- событийные компании Mini App: пользователь выбирает мероприятие, после чего
  приложение собирает 2–5 желающих именно на него, открывает RSVP, место
  встречи, безопасное знакомство и групповой чат;
- совместимость группы с выбранным размером компании, учёт блокировок и выход
  одним выключателем без раскрытия Telegram ID и контактов;
- серверная проверка подписи Telegram `initData` и срока её действия;
- кнопка запуска Mini App в `/start` и постоянном меню бота.
- встроенная аналитика открытий, активных пользователей и использования
  функций без сохранения текста обычных диалогов;
- обратная связь из Telegram и Mini App с уведомлением администратора и
  возможностью ответить пользователю через бота;
- приватный отчёт `/admin` с DAU/WAU/MAU, входами, топом функций, группами и
  непрочитанными обращениями.
- ежедневная сводка администратору за последние 24 часа со сравнением с
  предыдущими сутками и защитой от дублей после перезапуска.
- приватный дашборд в Mini App с периодами 7/30/90 дней: динамика DAU,
  входов и действий, возвращаемость, доля реально использующих бот,
  неактивные пользователи, частота использования, функции и каналы.
- одноразовый ненавязчивый опрос после семи дней без активности: ответ одной
  кнопкой, необязательный свободный комментарий и агрегаты причин в дашборде.

## Команды

| Команда    | Что делает                                              |
| ---------- | ------------------------------------------------------- |
| `/start`   | единое меню с переходами в разделы Mini App              |
| `/help`    | кратко объясняет разделы приложения                      |
| `/feedback` | принимает идею, вопрос или описание проблемы            |
| `/admin`   | приватная сводка работы бота для администратора           |
| `/feedbacks` | последние обращения пользователей для администратора   |
| `/reply ID текст` | отвечает пользователю на обращение              |

Старые команды `/profile`, `/find`, `/my`, `/schedule` и `/group` временно
сохранены как совместимые переходы в соответствующие разделы Mini App, но не
показываются в меню Telegram. Обычный текст не изменяет профиль.

## Требования

- Python 3.11 или новее;
- [uv](https://docs.astral.sh/uv/);
- токен Telegram-бота;
- ключ OpenAI API.

## Установка и запуск

Установите зависимости:

```bash
uv sync
```

Создайте файл `.env` из примера и укажите реальные ключи:

```bash
cp .env.example .env
```

```dotenv
BOT_TOKEN=telegram-bot-token
OPENAI_API_KEY=openai-api-key
# необязательно, по умолчанию text-embedding-3-small
EMBEDDING_MODEL=text-embedding-3-small
# дополнительные каталоги (необязательно)
TIMEPAD_API_TOKEN=timepad-token
TICKETMASTER_API_KEY=ticketmaster-key
# необязательно, час еженедельной отправки по Москве (по умолчанию 10)
DIGEST_HOUR_MSK=10
# публичный HTTPS-адрес Mini App
MINIAPP_URL=https://bot-ams.margleb.ru/r/app
# максимальный возраст Telegram initData, по умолчанию сутки
MINIAPP_AUTH_MAX_AGE_SECONDS=86400
# Telegram ID администраторов через запятую
ADMIN_TELEGRAM_IDS=123456789
# необязательно, час ежедневной админ-сводки по Москве (по умолчанию 10)
ADMIN_DAILY_REPORT_HOUR_MSK=10
# через сколько дней без активности спросить причину (по умолчанию 7)
INACTIVITY_FEEDBACK_DAYS=7
# опросы отправляются после этого часа по Москве (по умолчанию 18)
INACTIVITY_FEEDBACK_HOUR_MSK=18
# максимум новых опросов за один проход планировщика
INACTIVITY_FEEDBACK_BATCH_SIZE=50
```

Запустите бота одним из способов:

```bash
uv run event-bot
```

или:

```bash
uv run python main.py
```

API и статический интерфейс Mini App запускаются отдельно:

```bash
uv run python -m event_bot.webapp
```

По умолчанию процесс слушает порт `8080`, а публичные маршруты начинаются с
`/r`: интерфейс находится на `/r/app`, health-check — на `/r/health`. В
production порт публикуется только на `127.0.0.1` через `compose.yaml`, снаружи
к нему должен вести HTTPS reverse proxy. API не доверяет идентификатору из
запроса: каждый вызов заново проверяет HMAC строки `initData`, созданной
Telegram.

При старте бот создаёт файл базы `data/bot.db` и применяет схему. События
импортируются отдельно:

```bash
uv run python -m event_bot.import_events
```

Команда получает московские события ближайших 30 дней постранично из KudaGo.
Если заданы `TIMEPAD_API_TOKEN` и/или `TICKETMASTER_API_KEY`, дополнительно
опрашиваются соответствующие официальные API. Сбой одного источника не мешает
обновить остальные. Для каждого каталога печатаются добавленные, обновлённые и
пропущенные записи, ошибки и время выполнения. Повторный импорт обновляет строки
по паре `(source_id, external_id)`, а совпавшие название и время из разных
источников показываются пользователю одной карточкой.

После импорта посчитайте эмбеддинги событий:

```bash
uv run python -m event_bot.embed_events
```

Текст события состоит из названия, описания, тегов и площадки. Команда отправляет
изменившиеся события пачками, хранит `float32`-векторы как SQLite `BLOB` и при
повторном запуске пропускает записи с тем же `content_hash` и моделью.
Пользователям, сохранённым до обновления, достаточно один раз открыть `/profile`
и нажать «Верно», чтобы сохранить профильные векторы; до этого работает fallback
по тегам.

Для ручной проверки пяти характерных профилей запустите:

```bash
uv run python -m event_bot.check_search
```

После обновления старой установки сиды удаляются только явной отдельной
командой (вместе с относящимися к ним отметками и запросами):

```bash
uv run python -m event_bot.delete_seed_events
```

Без `uv run` те же команды имеют вид `python -m event_bot.import_events` и
`python -m event_bot.delete_seed_events` в активированном окружении. Каталог
`data/` в репозиторий не попадает.

## Хранение данных

База — SQLite в файле `data/bot.db`:

- `users` — профиль и расписание рассылки по `telegram_id`; списки (интересы,
  стоп-слова, дни) лежат в виде JSON, а эмбеддинги — как `BLOB`;
- `events` — мероприятия; исходная цена хранится в `price_text`, бесплатность
  отдельно в `is_free`, а уникальная пара `(source_id, external_id)` защищает
  повторный импорт от дублей; рядом хранятся эмбеддинг, модель и хеш исходного
  текста;
- `intents` — отметки по событиям: первичный ключ `(user_id, event_id)`,
  поэтому повторное нажатие обновляет строку, а не добавляет новую;
  `visibility_asked` помнит, что вопрос о видимости уже задавали;
- `requests` — запросы на знакомство со статусами `pending`, `accepted`,
  `rejected`; уникальная тройка события и пользователей запрещает повторы;
- `blocks` — глобальные блокировки пар пользователей.
- `event_groups` и `event_group_members` — компании вокруг конкретных
  мероприятий; человек может участвовать в разных компаниях, но только в одной
  на каждое событие;
- `event_group_messages` — встроенный чат событийной компании;
- `usage_events` — технические события использования: Telegram ID, функция,
  источник и время. Текст обычных сообщений и описаний профиля сюда не пишется;
- `feedback_messages` — обращения пользователей, источник, статус и время
  ответа администратора.
- `inactivity_feedback_prompts` — одноразовые опросы неактивных пользователей,
  результат доставки, короткая причина и время ответа.

Соединения используют WAL, общий таймаут ожидания записи и включённую проверку
внешних ключей. Новые колонки досоздаются при старте через `ALTER TABLE`,
поэтому база от прошлой версии не ломается. Архивные таблицы старого механизма
постоянных групп не используются приложением, но намеренно не удаляются при
обновлении. У старых событий поля источника и `status` остаются `NULL` до их
явного удаления.

## Как это работает

1. `/start` показывает четыре понятных перехода: афиша, сохранённые события,
   компании и профиль. Постоянная кнопка Telegram также открывает афишу.
2. Пользователь заполняет профиль в Mini App. Профиль и выбранный день
   еженедельной подборки сохраняются в SQLite.
3. При открытии афиши сервер сначала в SQL берёт активные московские события,
   не завершившиеся и попадающие в бюджет. Затем NumPy считает cosine similarity
   с положительным профилем и вычитает половину similarity с отрицательными
   интересами. Если совместимых векторов нет, используется прежний поиск по
   тегам. Бюджет, город и дата никогда не ослабляются смысловой близостью.
4. Пользователь нажимает «Найти компанию» на конкретном событии.
    Сервер атомарно присоединяет его к формирующейся компании этого мероприятия
    либо создаёт новую. Компания активируется со второго участника, не растёт
    больше пяти человек и не смешивает пользователей разных событий.
    Глобально заблокированные пользователи в одну компанию не попадают. После
    активации доступны RSVP, место встречи, чат и взаимное открытие контактов.
5. Middleware Telegram и ограниченный API Mini App фиксируют только разрешённые
    технические события: команды, открытия вкладок, карточек и действия. Команда
    `/admin` агрегирует их в DAU/WAU/MAU, входы и топ функций. Доступ проверяется
    по `ADMIN_TELEGRAM_IDS`.
6. `/feedback` или форма «Написать команде» создаёт обращение с номером и
    уведомляет администратора. `/feedbacks` показывает очередь, а
    `/reply ID текст` доставляет ответ пользователю и отмечает обращение
    обработанным.
7. После семи дней без действий бот один раз предлагает выбрать причину
    неактивности. Администраторы исключаются, повторных напоминаний нет.
    Вариант «Другое» добровольно переводит пользователя в обычную форму
    обратной связи, а причины без персональных данных видны в Mini App.
