# Event Bot

Telegram-бот, который собирает предпочтения пользователя и подбирает под них
мероприятия. Пользователь описывает интересы свободным текстом, OpenAI
преобразует сообщение в структурированный профиль, бот предлагает подтвердить
или исправить результат, сохраняет его в SQLite и по команде `/find` выдаёт
подходящие события.

## Возможности

- извлечение интересов и нежелательных активностей;
- распознавание удобных дней, бюджета и размера компании;
- подтверждение и повторное заполнение профиля через inline-кнопки;
- структурированный ответ OpenAI с проверкой через Pydantic;
- хранение профилей в SQLite — они переживают перезапуск бота;
- подбор до 5 будущих мероприятий по интересам, стоп-словам и бюджету.

## Команды

| Команда    | Что делает                                              |
| ---------- | ------------------------------------------------------- |
| `/start`   | приветствие и просьба рассказать о предпочтениях         |
| `/profile` | показывает текущий профиль с кнопками подтверждения      |
| `/find`    | подбирает мероприятия под сохранённый профиль            |

Любое обычное текстовое сообщение бот воспринимает как описание предпочтений
и пересобирает из него профиль.

## Требования

- Python 3.11 или новее;
- [uv](https://docs.astral.sh/uv/);
- токен Telegram-бота;
- ключ OpenAI API.

## Установка и запуск

Установите зависимости:

```bash
uv sync
```

Создайте файл `.env` из примера и укажите реальные ключи:

```bash
cp .env.example .env
```

```dotenv
BOT_TOKEN=telegram-bot-token
OPENAI_API_KEY=openai-api-key
```

Запустите бота одним из способов:

```bash
uv run event-bot
```

или:

```bash
uv run python main.py
```

При старте бот создаёт файл базы `data/bot.db`, применяет схему и наполняет
таблицу мероприятий демо-данными. Повторный запуск данные не дублирует.
Каталог `data/` в репозиторий не попадает.

## Структура проекта

```text
.
├── main.py                         # короткая точка входа
├── pyproject.toml                  # зависимости и настройки пакета
├── data/bot.db                     # локальная база SQLite (создаётся сама)
└── src/event_bot/
    ├── app.py                      # создание и запуск приложения
    ├── db.py                       # схема SQLite, профили, подбор событий
    ├── handlers.py                 # Telegram-команды и callback-обработчики
    ├── keyboards.py                # inline-клавиатуры
    ├── models.py                   # Pydantic-модели
    ├── profile_service.py          # извлечение и форматирование профиля
    └── storage.py                  # кеш профилей в памяти
```

## Хранение данных

База — SQLite в файле `data/bot.db`, две таблицы:

- `users` — профиль по `telegram_id`; списки (интересы, стоп-слова, дни)
  лежат в виде JSON, запись обновляется через UPSERT;
- `events` — мероприятия; уникальный индекс по паре «название + дата»
  защищает от дублей при повторном наполнении.

`ProfileStore` остаётся кешем в оперативной памяти: если после перезапуска
профиля там нет, он подтягивается из базы.

## Как это работает

1. Команда `/start` просит пользователя рассказать о предпочтениях.
2. Текст отправляется в OpenAI и преобразуется в модель `Profile`.
3. Бот показывает распознанные параметры и кнопки подтверждения или правки.
4. После подтверждения профиль сохраняется в SQLite.
5. По `/find` бот берёт будущие московские события, отсеивает их по бюджету,
   ранжирует по совпадению тегов с интересами (совпадения со стоп-словами
   понижают позицию) и отправляет до пяти карточек.
